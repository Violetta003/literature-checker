# Literature Checker 0.2.0

Исследовательский прототип для извлечения нумерованной библиографии из PDF и поиска записей в PubMed. Python 3.10+.

## Возможности

- Локальное чтение PDF через pdfplumber, список страниц с извлекаемым текстом.
- Поиск заголовков «Библиография», «Литература», «Список литературы», «Список использованных источников», References и Bibliography.
- Выделение ссылок с нумерацией `1.`, `1)` или `[1]`, объединение переносов строк, сохранение номеров страниц.
- Обработка первого найденного раздела. Следующий заголовок библиографии завершает его, чтобы не дублировать перевод списка.
- Эвристическое выделение названия, фамилий авторов, года и DOI. Поддерживается преимущественно форма «Фамилия И.О. Название. Журнал. Год».
- Поиск в PubMed по DOI при его наличии, иначе по выделенному названию.
- Сравнение названия, года, извлечённых фамилий и DOI. Сохранение исходной ссылки, кандидатов, причин решения и журнала запросов.
- Все результаты извлечения остаются доступными для ручной проверки.

## Установка

Откройте папку проекта в VS Code. В PowerShell активируйте существующее окружение или создайте новое.

```powershell
conda create -n reference-checker python=3.12 -y
conda activate reference-checker
python -m pip install -r requirements.txt
```

## Запуск

Из папки с `literature_checker.py` сначала запустите локальное извлечение. Для него доступ к сети и email не требуются.

```powershell
python .\literature_checker.py --pdf "C:\Documents\article.pdf" --extract-only --output .\results\extraction.json
```

Откройте JSON и проверьте `extraction.section_text`, количество ссылок и выделенные названия. Затем включите поиск. Передаются извлечённые поисковые данные ссылок, PDF остаётся локально.

```powershell
$env:NCBI_EMAIL = "ВАШ_КОНТАКТНЫЙ_EMAIL"
python .\literature_checker.py --pdf "C:\Documents\article.pdf" --limit 3 --output .\results\pilot.json
```

`--limit 3` проверяет первые три ссылки, остальные сохраняет со статусом `not_checked`. Для проверки всего списка уберите `--limit`. `--timeout 20` задаёт тайм-аут отдельной сетевой операции. До трёх попыток на запрос и последовательная обработка означают, что весь запуск может занять несколько минут.

Сохранён прежний запуск поиска по названию.

```powershell
python .\pubmed_search.py --title "Statistics review 4: Sample size calculations" --output .\results\single.json
```

Необязательный ключ NCBI можно передать через переменную окружения `NCBI_API_KEY`. Параметры email и ключа исключены из журнала отправленных параметров. Не загружайте `.env`, ключи и личные отчёты в репозиторий.

## Отчёт

В `extraction.pages` хранятся сведения о страницах. `has_text` показывает наличие извлечённых символов, но не подтверждает качество OCR или отсутствие ошибок кодировки. В `references` хранятся ссылки и их результаты.

| Статус ссылки | Значение |
|---|---|
| metadata_match | Один кандидат совпал по нормализованному названию, году, извлечённым фамилиям и указанному DOI. Разбор исходной ссылки требует проверки. |
| metadata_review | Получены кандидаты, но данных недостаточно, есть расхождения или неоднозначность. |
| not_found_in_pubmed | По сформированному запросу кандидатов нет. Источник может существовать вне PubMed или под другим названием. |
| request_failed | Ошибка запроса либо разбора ответа. |
| parsing_review | Не удалось выделить название или DOI для поиска. |
| not_checked | Поиск пропущен из-за режима извлечения или ограничения количества. |

Статусы документа `no_text_extracted`, `bibliography_not_found`, `reference_segmentation_failed`, `document_failed` требуют вмешательства человека. Ноль извлечённых ссылок не считается успешной проверкой. `completed_with_review` означает завершение обработки извлечённых ссылок, включая результаты, требующие проверки. Код выхода 1 обозначает сбой документа, извлечения или хотя бы одного сетевого поиска, 0 — завершённый запуск. Наличие библиографических расхождений отражается внутри отчёта.

`needs_human_review` пока всегда `true`. Сопоставление частичное — не проверяются журнал, том, номер, страницы, полнота и порядок авторов. Решение по фамилиям использует их наличие среди слов ответа, поэтому совпадение фамилий само по себе недостаточно для идентификации людей.

## Ограничения версии

Подключён PubMed. eLIBRARY, КиберЛенинка и Google Scholar отмечены в отчёте как `not_implemented`. Их подключение требует отдельной реализации и проверки условий доступа.

OCR отсутствует. Сложная многоколоночная вёрстка, ненумерованные списки, оглавления, колонтитулы, необычные инициалы, многочастные названия и повторяющиеся заголовки могут приводить к ошибкам. Эвристика названия заканчивает его на первой точке с пробелом после авторов, поэтому многофразовые названия могут обрезаться. Даты извлекаются эвристически. Скан со скрытым текстовым слоем может выглядеть как страница с текстом даже при плохом распознавании.

Поиск DOI пока не делает повторного поиска по названию при отсутствии результатов. Поиск по названию строгий, опечатки и переводы могут давать пропуски. PubMed имеет ограниченный тематический охват. Поддерживаются записи `PubmedArticle`, книги `PubmedBookArticle` дают явную ошибку. Ограничитель запросов работает внутри одного клиента, несколько процессов не координируются.

## Проверки

```powershell
python -m unittest -v
python .\literature_checker.py --pdf .\tests\fixtures\numbered.pdf --extract-only
```

Автономные тесты используют синтетические ответы API и маленькие PDF из `tests/fixtures`. Зависимость reportlab нужна только для первоначального создания этих уже включённых PDF, устанавливать её для запуска тестов не требуется. Результаты проведённых проверок описаны в `VALIDATION.md`.

## Структура

- `pdf_reader.py` — исходные функции чтения PDF, дополненные извлечением нумерованных ссылок и реквизитов.
- `pubmed_search.py` — существующий клиент PubMed с отдельным журналом на поиск и поиском DOI.
- `literature_checker.py` — общий CLI, последовательная обработка ссылок и сравнение метаданных.
- `test_pubmed_search.py`, `test_pipeline.py` — автономные тесты.
- `tests/fixtures` — синтетические входные PDF.
- `examples` — отчёты проверенных запусков.

## План исследования и ML

Версия 0.2.0 использует правила. Следующий исследовательский этап — разметить пары «исходная ссылка — кандидат» и сравнить правила с локальным классификатором, например логистической регрессией. Возможные признаки — сходство названий, совпадение фамилий, разность годов, совпадение DOI, пропуски полей. Для обучения нужны проверенные человеком метки соответствия. Сетевые сбои должны оставаться отдельным состоянием.

Качество извлечения, поиска и сопоставления оценивается раздельно. Оригиналы статей и все их синтетические варианты следует помещать в одну группу при разделении данных, чтобы варианты одной ссылки не попали одновременно в обучение и тест. Для пилота нужны корректные ссылки, опечатки, подмена авторов, подмена DOI, переводы и источники за пределами PubMed. Публикации до ChatGPT также требуют ручной проверки. Результаты на синтетических примерах не устанавливают качество на реальных статьях.

## GitHub

Создайте пустой репозиторий, распакуйте архив и откройте папку с файлами проекта. `.gitignore` исключает отчёты в `results/`, окружения и пользовательские PDF. Исключение позволяет включить синтетические тестовые PDF.

```powershell
git init
git add .
git commit -m "Add PDF bibliography extraction and PubMed pipeline"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
git push -u origin main
```

Архив не публикуется автоматически. Лицензия на собственный проект пока не выбрана. Код рассмотренных проектов не переносился. Использованы ваши исходные файлы, новая реализация и сторонняя библиотека pdfplumber. При публикации и подготовке статьи укажите инструменты и фактический вклад участников, включая применение ИИ при разработке.
